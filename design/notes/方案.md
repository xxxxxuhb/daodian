# 到点 · 备忘录方案

> 目标：给「到点」加一个能挂时间点的笔记模块——富文本、表格、图片，和待办/计划共用一套到点提醒。
> 结论先行：存储拆文件、编辑器用 Tiptap、图片走 Tauri asset protocol、提醒复用现有线程。

---

## 0. 一页结论

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 编辑器 | **Tiptap（ProseMirror）** | 表格官方、自定义节点最顺、存 JSON、无 CDN |
| 存储 | `notes/index.json` + `notes/<id>.json` | 列表秒开，保存不重写全量 |
| 图片 | 文件存 `attachments/<sha256>.<ext>` | 不塞 base64，避免文档膨胀 |
| 提醒 | 复用 `remind.rs`，给 `RemindTarget` 加 `Note` | 免打扰、合并、退避全都白拿 |
| 备份 | 索引全量、正文按 mtime 增量、附件硬链接 | 否则每天全量复制会爆 |
| 搜索 | 索引里的 `text` 字段 | 不改现有 Ctrl+K 结构 |

---

## 1. 定位

不是「又一个 Notion」，而是 **能挂在时间点上的笔记**：

- 只是一篇笔记（会议记录、需求草稿、排障过程）；
- 也能设一个到点时间（到点提醒你「该看这篇了」）；
- 还能挂在一份计划或一个阶段下（提测前的检查清单）。

它和待办、计划共用同一套「到点」逻辑，所以不是外挂模块。

---

## 2. 范围

### P1 · 能用（6 天）

- 笔记列表：全部 / 最近 / 有到点 / 已归档，置顶
- 编辑器：标题、段落、标题级别、列表、引用、代码块、分割线、撤销重做
- 自动保存（800ms 防抖 + 切页 flush）
- `Ctrl K` 能搜到笔记标题与正文摘要

### P2 · 好用（6 天）

- 表格：插入、增删行列、合并单元格、列宽拖拽、表头
- 图片：粘贴 / 拖拽 / 选择文件，缩略图 + 原图查看
- 任务清单（可勾选）、链接、高亮
- Markdown 快捷输入（`#`、`-`、`[]`、```、`>`）
- 附件孤儿清理

### P3 · 连起来（4 天）

- 到点提醒（笔记级）
- `@` 引用待办 / 计划 / 阶段，点击跳转
- 标签、归档
- 导出 Markdown / HTML

### 明确不做

- 多端实时协同（Yjs）——单机场景用不上，复杂度翻倍
- 版本历史（先靠每日备份兜底）
- 网页剪藏、OCR、PDF 批注

## 4. 数据模型

### TypeScript

```ts
export interface NoteIndex {
  id: string
  title: string
  summary: string        // 纯文本前 140 字，列表用
  text: string           // 纯文本前 4KB，搜索用
  tags: string[]
  dueAt?: number         // 可选到点
  pinned: boolean
  archived: boolean
  thumb?: string         // 首张图缩略图 hash
  attachments: string[]  // 引用到的附件 hash
  createdAt: number
  updatedAt: number
}

export interface Note extends NoteIndex {
  doc: JSONContent       // ProseMirror 文档
  docVersion: number     // schema 版本，迁移用
}
```

### Rust

```rust
#[derive(Serialize, Deserialize, Clone)]
#[serde(rename_all = "camelCase")]
pub struct Note {
    pub id: String,
    pub title: String,
    pub doc: serde_json::Value,   // 原样存，Rust 不解释
    pub doc_version: u32,
    #[serde(default)] pub tags: Vec<String>,
    #[serde(default)] pub due_at: Option<i64>,
    #[serde(default)] pub pinned: bool,
    #[serde(default)] pub archived: bool,
    #[serde(default)] pub created_at: i64,
    #[serde(default)] pub updated_at: i64,
}
```

**Rust 不解析 doc** —— 只在保存时抽出纯文本和附件列表（前端算好一起传上来更省事，见 §12）。

## 5. 存储布局

```
<数据目录>/
├─ store.json            待办 + 计划（不动）
├─ templates.json
├─ settings.json
├─ notes/
│  ├─ index.json         元数据，列表页只读这个
│  └─ n_1793….json       单篇正文
├─ attachments/
│  ├─ a3f9….png          原图（sha256 命名，天然去重）
│  └─ a3f9…@480.webp     缩略图
└─ backups/
```

**为什么拆**：现有 `store::Library` 是「全量读、全量写」。笔记一旦带图，单文件会到几十 MB，每次改动都重写全文。拆成「索引 + 单篇」后：列表页只读几百 KB，保存只写一篇。

---

## 6. 读写与一致性

- **自动保存**：编辑停手 800ms 落盘；切笔记 / 切 tab / 关窗口前强制 flush。
- **原子写**：先写 `<id>.json.tmp`，再 `rename` 覆盖，避免半截文件。
- **索引更新**：保存正文后同步写 `index.json`（同样是 tmp + rename）。
- **冲突**：单机单实例（已有 single-instance 插件），不需要锁；但打开笔记时记 `updatedAt`，保存前对不上就提示「这篇在别处被改过」。
- **崩溃恢复**：索引损坏时从各篇 `<id>.json` 重建索引（标题取 doc 第一个 heading，摘要取纯文本）。

## 7. 富文本选型

| 库 | 内核 | Vue 3 | 表格 | 图片 | 体积(gz) | 许可 | 判断 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **Tiptap** | ProseMirror | 官方 `@tiptap/vue-3` | 官方 TableKit，合并单元格 / 列宽拖拽 | 官方 + 自定义 NodeView | ~150KB | MIT | **选它** |
| Milkdown | ProseMirror + Markdown | 有 | 有（GFM） | 有 | 中 | MIT | Markdown 优先，样式固定 |
| wangEditor 5 | 自研 | 官方包 | 内置 | 内置 | 小 | MIT | 最快出效果，扩展性弱 |
| Lexical | Meta | 社区封装 | 插件 | 有 | 中 | MIT | Vue 不成熟 |
| Quill 2 | Delta | 社区封装 | 无官方表格 | 基础 | 小 | BSD | 表格要自己搭 |
| Editor.js | 块编辑 | 社区 | 弱 | 有 | 小 | Apache-2 | 嵌套与表格弱 |

**结论：Tiptap。** 决定性理由：表格是刚需且官方直接给；自定义节点（引用待办卡片）只有 ProseMirror 能干净实现；存 JSON 不存 HTML，迁移和导出都可控。

**备选**：如果要求「三天上线」，用 wangEditor 5，代价是后面做引用节点要重写。

## 8. 图片管线

```
粘贴 / 拖拽 / 选文件
   → 读字节 → sha256 去重（存在就直接复用）
   → 写 attachments/<hash>.<ext>
   → Rust 生成 480px 缩略图 <hash>@480.webp
   → 编辑器插入 Image 节点：
        src = convertFileSrc(原图路径)
        data-thumb = 缩略图路径
```

**Tauri 配置**（`tauri.conf.json`）：

```json
"app": {
  "security": {
    "assetProtocol": { "enable": true, "scope": ["$APPDATA/**"] },
    "csp": "default-src 'self'; img-src 'self' asset: http://asset.localhost data: blob:"
  }
}
```

**传输方式**：大图不要走 `invoke` 的 number[]（10MB 会卡死 IPC）。前端拿到 `File` 后先用 `@tauri-apps/plugin-fs` 的 `writeFile` 写到命令返回的临时路径，再调 `note_attachment_commit(hash)` 归位。

**孤儿清理**：

1. 删除笔记 → 从索引移除引用；
2. 每 24h 扫一次：`attachments` 里所有文件 hash ∉ 索引中任何 `attachments` 并集 → 删除（保留 7 天宽限）；
3. 单篇内删图时立即释放引用，但文件交给上面这步删。

**限额**：单张 10MB，超了提示压缩；同一笔记图片总数 200 张。

## 9. 搜索

- 索引里已含 `text`（正文纯文本前 4KB），`Ctrl K` 直接在内联数组里匹配即可，无需索引库。
- 排序权重：标题命中最前 > 标签 > 正文。
- 点开结果后，在正文里高亮并滚动到第一处命中（用 ProseMirror 的 `setTextSelection`）。
- 笔记超过 5000 篇再考虑建倒排索引（当前量级不需要）。

## 10. 提醒集成

```rust
pub enum RemindTarget {
    Todo { id: String },
    Stage { plan: String, stage: String },
    Note { id: String },          // 新增
}
```

- `next_due_at()` 遍历 `notes` 中 `due_at` 未提醒的条目，取最近。
- 通知文案：`「备忘录 · 1.2 版本提测清单」`，点通知打开该篇。
- 免打扰、每小时上限、合并、退避 **全部复用** `remind.rs`，不改逻辑。
- 笔记的到点只响一次，不重复（和待办一致）。

## 11. 备份与迁移

现有 `backup.rs` 每天复制 `store.json / templates.json / settings.json`。加入笔记后：

| 内容 | 策略 |
| --- | --- |
| `notes/index.json` | 全量，随每日快照 |
| `notes/<id>.json` | 只复制当天 mtime 有变化的 |
| `attachments/**` | 同盘用硬链接（`CreateHardLinkW`），不重复占空间 |

恢复时：索引 + 正文 + 附件一起回滚；附件缺失就显示占位图，不阻塞正文。

**迁移**：`note.docVersion` 从 1 开始。以后改 schema 时写 `migrate_note_doc(v1 -> v2)`，与现有 `migrate_legacy_json` 放一起。

## 12. Tauri 命令

```rust
notes_index()                    -> NoteIndexFile
note_load(id: String)            -> Note
note_create(seed: Option<String>) -> Note
note_save(note: Note, text: String, summary: String) -> NoteIndex
note_delete(id: String)
note_set_meta(id, patch: NoteMetaPatch)   // pinned / archived / tags / dueAt
note_attachment_commit(tmp: String, ext: String) -> Attachment
note_export(id, format: "md" | "html") -> String
```

- 纯文本 `text`/`summary` 由前端从 doc 提取后一起传（Rust 不引 ProseMirror 的 schema）。
- 所有命令返回更新后的索引项，前端直接替换本地缓存，避免再拉一次列表。

## 16. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 备份膨胀 | 正文增量 + 附件硬链接（§11） |
| 索引与正文不一致 | 索引可重建；启动时校验 `updatedAt` |
| IPC 传大图卡死 | 走 `plugin-fs` 写文件，不进 `invoke` |
| Tiptap 版本升级破坏 schema | `docVersion` + 迁移函数 + 保存前校验 |
| CSS 污染 | 编辑器样式全部挂在 `.note-editor` 作用域下 |
| 与现有 `styles.css` 冲突 | 新样式单独 `notes.css`，用现有 token |
