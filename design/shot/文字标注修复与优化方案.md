# 到点 · 文字标注修复与优化方案

> 状态：**修复方案**（2026-11）· 不改产品交互。
> 现象：选了文字工具、输入文字后，标注没有出现在冻结图上；或者输入框一闪就没了。
> 结论先行：**渲染层大概率没问题，问题在文字输入的提交状态机**。两个主因：
> 1. 点空白提交时，`onDown` 先 `commitText`，又继续走「新选区」分支，把刚加进去的 `shapes` 清空了。
> 2. 中文输入法按 Enter 选候选词时，`@keydown.enter.prevent` 直接把输入框提交/移除了，候选词还没上屏。
> 另有两个次要问题：提交后工具仍是文字工具，点选区内部会立刻开一个新的空输入框；blur 和 pointerdown 可能重复提交。

---

## 0. 一页结论

| 优先级 | 修复 | 预期 |
| --- | --- | --- |
| R1 | 点空白提交时 consume 这次 pointerdown，不再继续新选区 | 点外面文字不会消失 |
| R2 | 输入法 composition 期间不提交；Enter 只在非组合态生效 | 中文候选词能上屏 |
| R3 | 新选区只在真正拖动超过 3px 时清空标注 | 单击空白不会误删标注 |
| R4 | `commitText` 后显式 `schedulePaint`，并把工具切回移动 | 提交即可见，不再弹空输入框 |
| R5 | blur / pointerdown 去重，输入聚焦前不抓 pointer capture | 不再双重提交/失焦 |
| R6 | 补文字标注的单元/手工测试 | 英文、中文、点击、Esc、导出全覆盖 |
| O1 | 抽出文字编辑状态机，输入框只做展示 | 后续加多行/字号不再改一堆分支 |
| O2 | 输入框提示、宽度自适应、可选多行 | 体验更稳，不阻塞本次修复 |

**建议顺序：R1 → R2 → R3 → R4 → R5 → R6；O1/O2 随后。**

## 1. 复现与根因

### 1.1 文字标注的现有流程

```text
点文字工具 T
  → 在选区内 pointerdown
  → onDown：textAt = 点；return
  → input 出现并聚焦
  → 输入文字
  → Enter / 点空白 / 失焦
  → commitText：textAt=null；textValue=""
      shapes += { kind:"text", x, y, text, color }
  → watch(shapes) → schedulePaint → canvas 画文字
```

### 1.2 根因 A：点空白提交时，刚提交的文字被新选区清掉

`onDown` 当前顺序（简化）：

```ts
if (textAt.value) {
  commitText();          // 文字加进 shapes
}
// 没有 return，继续往下
if (phase === "edit" && current && inside && tool === "text") {
  textAt.value = point;  // 点在选区内：又开一个空输入框
  return;
}
phase.value = "select";
shapes.value = [];       // 点在选区外：刚提交的文字被清空
selection.value = { ... };
```

**结果**：

- 点选区外：文字提交后立刻被 `shapes.value = []` 清掉，看起来「没生效」。
- 点选区内：文字留下了，但又弹出一个空输入框，看起来像没提交。
- 点工具栏/退出：输入框 blur 提交，随后可能被其他逻辑清掉。

这是最可能的主因，尤其是用鼠标点空白来「确认」文字的人。

### 1.3 根因 B：中文输入法 Enter 被提前拦截

输入框当前绑定：

```html
@keydown.enter.prevent="commitText"
@keydown.esc.stop.prevent="applyEscape"
@blur="commitText"
```

中文输入法在**组合态**下按 Enter 是「选候选词」，此时：

- `event.isComposing === true`；
- `keydown.enter` 仍然触发；
- `.prevent` 会阻止输入法默认行为；
- `commitText` 可能拿到空字符串或拼音，随后 `textAt=null`，输入框消失。

用户看到的就是「字还没上屏，输入框没了」。

### 1.4 根因 C：工具没切走，点选区内又开空输入框

提交后 `tool` 仍是 `text`；下一次在选区内点击：

```ts
if (phase === "edit" && current && inside && tool === "text") {
  textAt.value = point;
  textValue.value = "";
  return;
}
```

于是文字确实画上去了，但空输入框又出现，用户以为没生效。

### 1.5 根因 D：blur 与 pointerdown 重复提交/清空

- pointerdown 在输入框外发生时，浏览器可能先 blur 再 pointerdown，也可能反过来；
- `@blur="commitText"` 和 `onDown` 里的 `commitText()` 都可能执行；
- 如果 blur 先把 `textAt` 置空，`onDown` 仍会继续走「新选区」分支并清空 `shapes`；
- 如果 pointerdown 先提交，随后 blur 再次 `commitText`，因为 `textAt` 已空，通常无害，但时序不稳。

### 1.6 渲染层检查

目前的绘制逻辑：

- `shapes` 里的 text 是 `{ kind:"text", x, y, text, color }`；
- `paint()` 用 `ctx.setTransform(dpr, 0, 0, dpr, -box.x*dpr, -box.y*dpr)`，把屏幕坐标映射到选区局部 canvas；
- `drawShapes` 用 `strokeText` + `fillText` 画文字，字号 18；
- `shapes` 变化会触发 `watch` → `schedulePaint`。

**结论**：只要 text 真的进了 `shapes`，它应当能画出来。当前问题优先按状态机修，不要先怀疑 canvas 变换。

## 2. 修复方案

### R1. 点空白提交时，立即 consume 这次 pointerdown（P0）

**目标**：点空白只负责「提交文字」，不能同时在同一次点击里开始新选区。

**改法**：

```ts
function onDown(event) {
  if (event.button === 2) { ... }
  if (event.button !== 0) return;

  if (textAt.value) {
    event.preventDefault();
    commitText();
    return;                 // 关键：不要再走后面的 select 分支
  }

  // 处理 blur 先于 pointerdown 的情况：刚提交过，消费一次点击
  if (justCommittedText()) {
    event.preventDefault();
    return;
  }

  // 其余逻辑...
}
```

- `justCommittedText()` 用时间戳/标记实现，窗口建议 150–250ms；
- 用户要点空白后再拖新选区，需要第二次按下；这是可接受的，避免丢标注；
- **最小止血**：只在 `onDown` 的 `commitText()` 后加 `return`，就能解决「点空白丢字」；中文输入法还要 R2。
- 不要在 `commitText` 里设置永久 flag，避免吞掉很久之后的点击。

### R2. 输入法 composition 期间不提交（P0）

**目标**：中文/日文输入法选候选词时，Enter/Esc 先交给输入法；组合结束后再确认。

**改法**：

1. 增加 `composing` 状态：

```ts
const composing = shallowRef(false);
let pendingBlur = false;
```

2. 输入框事件：

```html
@compositionstart="composing = true"
@compositionend="onCompositionEnd"
@keydown="onTextKey"
@blur="onTextBlur"
```

3. 按键处理：

```ts
function onTextKey(event: KeyboardEvent) {
  if (event.isComposing || composing.value) return; // 让输入法处理
  if (event.key === "Enter") {
    event.preventDefault();
    commitText();
  } else if (event.key === "Escape") {
    event.preventDefault();
    cancelText();
  }
}
```

4. 组合结束：

```ts
function onCompositionEnd() {
  composing.value = false;
  if (pendingBlur) {
    pendingBlur = false;
    commitText();
  }
}
```

5. 失焦：

```ts
function onTextBlur() {
  if (composing.value) {
    pendingBlur = true;
    return;
  }
  commitText();
}
```

**注意**：不要再用 `.prevent` 写死在 Enter 上；否则组合态永远收不到输入法默认行为。

### R3. 新选区只在真正拖动时清空标注（P0/P1）

**目标**：单击空白不应清空已有标注；只有用户明确拖出一个新选区时才丢弃旧标注。

**改法**：

1. `onDown` 在选区外时，不立刻 `shapes.value = []`；先记一份旧状态：

```ts
pendingSelect = {
  previousSelection: selection.value,
  previousShapes: shapes.value,
  cleared: false,
};
```

2. `onMove` 的 select 分支：当新框宽/高 > 3px 且尚未清空时，再 `shapes.value = []`。
3. `onUp`：
   - 新框 <3px：恢复 `previousSelection` / `previousShapes`，视为单击，不改变标注；
   - 新框 ≥3px：进入编辑态，旧标注已清空。
4. 移动/缩放选区不触发清空。

这也能顺手修掉「误点空白丢标注」的通用问题。

### R4. 提交后显式重绘，并切回移动工具（P1）

**目标**：提交文字后立刻可见，不再出现空输入框。

**改法**：

- `commitText` 里 `shapes.value = [...shapes.value, shape]` 后调用 `schedulePaint()`，不只依赖 `watch`；
- 提交成功后 `tool.value = "move"`；用户要再写文字，重新按 `T`；
- `commitText` 做幂等：`textAt` 为空直接 return；空文本只关闭输入框，不产生 shape；
- 不要在 `commitText` 里改 `selection` / `phase`；
- 如果希望连续写多段文字，可保留 `text` 工具，但必须让下一次点击明确「新建文字」，而不是自动弹空框；当前建议先切回 move。

### R5. 聚焦、pointer capture、blur 去重（P1）

**目标**：输入框能稳定拿到焦点，点击不会双重提交。

**改法**：

1. 在 `onDown` 里把文字工具的分支放到 `stage.setPointerCapture` **之前**；文字输入不需要 pointer capture，避免抢焦点。
2. `textAt` 设置后 `nextTick` 聚焦；可再加 `textRef.value?.focus({ preventScroll: true })`。
3. `commitText` 设置一个短时标记（例如 `lastCommitAt`），让紧随其后的 pointerdown/blur 不重复清空/开框。
4. `commitText` 和 `cancelText` 分开：
   - commit：空文本不产生 shape，关闭输入框；
   - cancel：清空 `textValue`，关闭输入框，不动 selection/shapes。
5. `applyEscape` 在 `composing` 时直接返回，把 Esc 留给输入法；组合结束后再按 Esc 才取消文字。

### R6. 测试（P1）

**单元/纯逻辑**：

- `escapeAction({ typing:true, ... })` 返回 `cancel-text`；
- `commitText`：空文本不产生 shape；有文本产生 `kind:"text"`；
- `composing=true` 时 Enter 不提交；
- 单击空白恢复旧 selection/shapes；拖动 >3px 才清空。

**手工**：

1. 英文：点 T → 输入 hello → Enter → 文字可见；点空白 → 文字还在。
2. 英文：点 T → 输入 hello → 点选区外 → 文字可见，不出现新输入框/新选区。
3. 中文：输入拼音 → Enter 选候选词 → 输入框还在 → 再 Enter 提交 → 文字可见。
4. 中文：输入拼音 → 点空白 → 候选词提交，文字可见，标注不丢。
5. 空文本 Enter：不产生文字，不丢选区。
6. Esc：组合态先取消输入法；非组合态取消文字；再按 Esc 退回选区。
7. 提交后工具是移动；点选区内不会自动弹空输入框。
8. 撤销：文字 shape 可被 Ctrl+Z 撤销。
9. 复制/另存：文字出现在导出图里。
10. 100%/125%/150% DPI、多屏下文字位置不偏。

## 3. 优化

### O1. 抽一个文字编辑状态机（后续）

把 `idle / selecting / editing / typing / composing` 抽成纯函数 reducer，Vue 只负责渲染输入框。这样：

- Enter/Esc/blur/pointerdown 的优先级有单一入口；
- 单测可以直接覆盖，不用起 WebView；
- 以后加多行、字号、背景不用改一堆分支。

### O2. 输入体验

- 输入框上方/下方显示一行提示：`Enter 确认 · Esc 取消`；
- 输入框宽度随内容增长，最小 80px，最大不超过选区；
- 文字 shape 目前固定 18px；后续可在工具条加字号（P2）；
- 多行文字放 P2，不要和本次修复混做；
- 文字超出选区时按选区裁剪，这是现有行为，保持。

### O3. 可观测性

- 在 commit/cancel 时打一条 debug 日志（仅 debug 构建）：`text commit len=…`；
- 记录 `isComposing` 和 pointerdown/blur 顺序，便于复现输入法问题；
- 不要记录文字内容本身。

## 4. 验收

1. 英文文字：输入 → Enter → 可见；点空白后仍可见。
2. 中文文字：组合态 Enter 选词不提交；组合结束再 Enter 提交，文字完整。
3. 点选区外提交：文字保留，不出现新输入框/新选区。
4. 点选区内（提交后）：工具已切回移动，不自动弹空输入框。
5. 空文本：不产生 shape，不丢选区/标注。
6. Esc：组合态不影响输入法；非组合态取消文字；再按退回选区。
7. blur：点工具栏/别处只提交一次，不重复/不丢字。
8. 撤销、复制、另存、贴图都包含文字。
9. 100%/125%/150% DPI、多屏下文字位置和大小正确。
10. 不出现「文字提交后又被清空」的回归。

---

## 5. 这一轮不做什么

- 不做多行文字、字号选择、文字背景、字体选择；放下一个版本。
- 不重写 canvas 渲染；先确认状态机修复后文字能画出来。
- 不改文字工具的产品入口；仍然是 `T`。
- 不为文字单独做一套 DOM 覆盖层；当前 canvas 够用。

---

## 6. 一句话

**文字标注不是画不出来，而是「提交后又被新选区清掉」和「中文 Enter 被提前拦截」；先把 pointerdown 的提交 consume 掉、把 composition 期间的 Enter 放给输入法，再让提交后切回移动工具，文字就会稳定出现。**
