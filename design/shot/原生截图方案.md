# 到点 · 原生截图方案（对齐 PixPin）

> 状态：架构方案（2026-11）· 不改产品交互，替换冻结层的渲染载体。
> 背景：PixPin 3.6.6 是 Qt5/C++ 原生截图；当前到点是 Tauri + Vue + 全屏 WebView2。差距不在某个函数，而在原生窗口/原生场景和每屏一个 WebView。
> 结论：冻结本身保留，渲染层换成原生 Win32 + DIB/Direct2D。先做原生冻结/选区/复制/另存，再用「选区大小的 WebView 编辑器」复用现有标注；纯原生标注作为后续选项。OCR、长截图、GIF 放最后。不要一次重写所有功能。

---

## 0. 一页结论

| 阶段 | 内容 | 工期 | 结果 |
| --- | --- | --- | --- |
| N0 | 原生冻结 + 选区 + 复制 / 另存 | 3–5 天 | 热键 100–200ms 可见、无偏移、无 WebView |
| N0.5 | 原生选区 + 选区大小的 WebView 标注编辑器 | 2–4 天 | 复用现有标注，不回到全屏 WebView |
| N1 | 纯原生标注 + 工具条 + 文字（可选） | 1–2 周 | 矩形/箭头/画笔/文字/撤销，彻底去 WebView |
| N2 | 原生贴图 + 多屏/DPI 收口 | 3–5 天 | 贴图原位、跨屏不错位、退出清理 |
| N3 | OCR / 长截图 / GIF | 3–6 周 | 功能对齐 PixPin 的一部分，按需做 |

推荐先做 N0 + N0.5：N0 解决慢和偏，N0.5 用现有 Vue 标注把「能标注」补回来。N1 纯原生标注是长期选项，不是第一版必须。不要先做 OCR/滚动/GIF。

---

## 1. 为什么走原生

从本机 PixPin 3.6.6 日志看，双屏一次截图大约 267ms：

```text
15:39:26.004  快捷键
15:39:26.010  截图开始
15:39:26.012  抓 2880×1920，99ms
15:39:26.121  抓 2560×1440，49ms
15:39:26.175  两屏抓完
15:39:26.188  原生截图窗口构造完成（约 12ms）
15:39:26.257  场景刷新完成
15:39:26.271  窗口显示
```

它也是先截后显，所以冻结不是问题；快在原生捕获和原生窗口。

当前到点的问题：

- 每屏一个全屏 WebView2；
- 图像经 BMP/Blob/img 解码；
- WebView2 的 surface、DPI、窗口位置需要自定义对齐；
- 出现偏移、首帧慢、文字/选区卡顿。

原生窗口没有 WebView surface 层，DPI 和图像尺寸就是一对一的物理像素，这是 PixPin 稳的根本原因。

---

## 2. 目标架构

```text
Tauri 主进程
  ├─ 主窗口 / 设置 / 数据 / 托盘 / 快捷键（保留 Vue）
  ├─ shot 调度（session / generation / 临时文件清理）
  └─ 原生截图模块（Windows）
       ├─ Capture：GDI（先用）→ WGC/DXGI（后续）
       ├─ Overlay：每屏一个 Win32 窗口（topmost、no-activate）
       ├─ Render：DIB + GDI/Direct2D 画冻结图、选区、标注
       ├─ Input：鼠标 / 键盘 / 原生 EDIT（文字 IME）
       ├─ Actions：复制 / 另存 / 贴图
       └─ Pin：原生置顶小窗
```

原则：

- 冻结图不再进 WebView；
- 全屏覆盖层不再用 WebView；
- Vue 只保留主窗口、设置抽屉、帮助；
- 截图数据不经过 IPC 大图；原生模块直接持有 BGRA；
- 所有屏幕几何用 Win32 物理像素，一套坐标。

---

## 3. N0：原生冻结 + 选区 + 复制 / 另存（3–5 天）

现有 src-tauri/src/shot_native.rs 已经是原型：每屏一个 Win32 窗口、DIB、选区、复制/另存/标注/重选/退出按钮。N0 在它上面收口，不重写。

### 3.1 窗口

- 每屏一个 WS_POPUP + WS_EX_TOPMOST + WS_EX_TOOLWINDOW + WS_EX_NOACTIVATE 窗口；
- 位置/尺寸用 Win32 EnumDisplayMonitors + GetMonitorInfoW 的 rcMonitor（物理像素）；
- 主线程 per-monitor v2；不要用 Tauri 的 monitor 几何混算；
- 先抓 active 屏，先显示；其他屏并行抓，抓完补；
- 先抓后显，覆盖层不会进截图。

### 3.2 绘制

- CreateDIBSection（top-down 32bpp）+ BitBlt 冻结帧；
- WM_PAINT 画图；
- 选区：半透明暗层 + 边框 + 8 个把手；
- 尺寸标签、十字光标、放大镜后续加；
- 颜色/DPI 不做 CSS/zoom 变换，1:1 物理像素。

### 3.3 输入

- WM_LBUTTONDOWN/MOUSEMOVE/LBUTTONUP：拖选、移动、改大小；
- WM_KEYDOWN：Esc 退出、Enter 复制、方向键微调；
- 右键逐层退出；
- 先不做复杂标注，保留按钮：复制 / 另存 / 标注 / 重选 / 退出。

### 3.4 动作

- 复制：arboard 或 Win32 CF_DIB；
- 另存：image/WIC 写 PNG，Tauri 另存对话框；
- 标注：先 handoff 到现有 WebView 标注层（过渡），N1 再替换；
- 贴图：N2 做原生，N0 先保留现有。

### 3.5 N0 验收

1. 热键 → active 屏可见 ≤ 200ms；4K 单屏 ≤ 300ms。
2. 冻结图与桌面 1:1；100%/125%/150% 不偏。
3. 多屏、负坐标、竖屏正确。
4. 复制/另存内容正确；不出现 BMP/PNG 偏移。
5. 退出后无残留窗口/DIB。

### 3.6 N0.5：选区大小的 WebView 标注编辑器（推荐先做）

**为什么**：当前 shot_native.rs 只有复制 / 另存 / 重选 / 退出；标注按钮 mark_selection 调 annotate_from_native，会销毁原生窗口并打开全屏 WebView 标注层。所以「原生窗口本身没有标注」是事实，但不是原生不能标注，而是还没实现。纯原生标注要 1–2 周；先用选区大小的 WebView 编辑器，可以复用现有标注代码，2–4 天就能把标注补回来。

**做法**：

1. 原生选区完成后，点「标注」或双击选区：
   - 从原生帧里按选区裁剪出 BGRA（现有 selection_pixels 已经有）；
   - 打开**一个**编辑器窗口，位置 = 选区屏幕位置，大小 = 选区物理尺寸 / scale；
   - 把裁剪帧交给编辑器；ShotOverlay 进入 crop 模式，复用现有 canvas 标注、文字输入、撤销；
   - 工具条放在编辑器窗口内部，或紧挨选区的一个小窗口。
2. 编辑器窗口**不是全屏**：冻结图、选区、标注都在一个小窗口里，1:1 像素，不再有全屏 WebView 的 surface/DPI 偏移。
3. 原生窗口的「复制 / 另存」保留，不需要标注时直接走原生；只有「标注」才开编辑器。
4. 复制 / 另存 / 贴图后关闭编辑器和原生窗口；「重选」关闭编辑器回到原生选区。
5. 只预热**一个**编辑器 WebView，不要每屏一个；选区完成后创建编辑器，100–200ms 可接受。
6. 多屏：编辑器放在选区所在屏，负坐标/DPI 用物理到逻辑换算；选区很小、工具条放不下时，用最小窗口尺寸或独立小工具条。

**代价**：

- 编辑器窗口创建有一次 WebView 成本；
- 工具条可能盖住选区底部，需要上下翻转；
- 原生和 WebView 两套关闭/会话状态要协调；
- 选区移动/缩放仍由原生做，编辑器只负责标注。

**验收**：

1. 原生选区 → 点标注 → 选中区域以 1:1 显示在编辑器里。
2. 矩形/箭头/画笔/文字/撤销可用；中文 IME 正常。
3. 复制/另存/贴图包含标注。
4. 编辑器不出现在截图里；关闭后原生窗口和临时帧清理干净。
5. 100%/125%/150% DPI 下编辑器和选区对齐，不偏。
6. 不出现全屏 WebView 的那种冻结图偏移。

## 4. N1（可选）：纯原生标注 + 工具条 + 文字（1–2 周）

> 如果 N0.5 的选区大小编辑器已经够用，N1 可以不做；只有要彻底去 WebView、追 PixPin 级性能/一致性时再做。

### 4.1 渲染

- Direct2D + DirectWrite 画矢量标注；或先用 GDI+，接口保持可替换；
- 标注层与冻结图同一坐标系（物理像素）；
- 形状：矩形 / 箭头 / 画笔 / 文字；后续椭圆/荧光笔/马赛克/序号；
- 撤销/重做：形状数组 + 50 步；
- 选区内裁剪；选区移动时标注跟随，缩放不缩放标注。

### 4.2 文字输入

这是原生化的最大坑，建议直接用 Win32 控件：

- 点击文字工具时，在点击位置创建一个 EDIT（或 RichEdit）子控件；
- 字体、颜色、透明背景；
- 支持中文 IME；
- Enter 提交、Esc 取消、blur 提交；
- 提交后把文本写入标注数组，销毁 EDIT；
- 不要在原生层自己实现 IME。

### 4.3 工具条

- 原生 owner-draw 工具条，或用一个小尺寸的 WebView 工具条；
- 推荐原生 owner-draw：位置跟选区、无 DPI 缩放问题；
- 按钮：移动 / 矩形 / 箭头 / 画笔 / 文字 / 撤销 / 复制 / 贴图 / 另存 / 关闭；
- 颜色/线宽用弹出小面板；
- 工具条不能挡住选区，四角要能翻转。

### 4.4 键盘/焦点

- 覆盖层窗口 no-activate，但需要键盘时主动 SetFocus；
- 文字 EDIT 获得焦点时，Esc/Enter 由 EDIT 处理，不要被全局钩子抢；
- 全局快捷键再按一次退出；
- 多屏只允许 active 屏接收键盘。

### 4.5 N1 验收

1. 矩形/箭头/画笔/文字都能画。
2. 中文输入法能输入、提交、取消。
3. 撤销/重做 50 步。
4. 标注在 100%/125%/150% 下位置正确。
5. 复制/另存包含标注。
6. 拖选/画笔 60fps。

---

## 5. N2：原生贴图 + 多屏/DPI 收口（3–5 天）

- 贴图用原生 topmost 窗口 + DIB；
- 原位放置、不进任务栏、悬停控件、拖动、滚轮缩放；
- 多屏：每屏一个覆盖层，active 先出，其他补；
- 退出/崩溃清理 DIB/临时文件；
- 移除 freeze/live 的 WebView surface 路径；保留 feature flag 回退。

---

## 6. N3：OCR / 长截图 / GIF（后续，3–6 周）

按需做，不要一次全上：

- OCR：Windows.Media.Ocr 或本地 ONNX；原生选区 → 文本；
- 长截图：OpenCV 拼接或自写模板匹配；
- GIF：WGC/DXGI 抓帧 + GIF 编码；
- 这些是独立原生模块，不要塞回 WebView。

---

## 7. 迁移与开关

- 设置里保留 captureMode：native / freeze / live；
- N0 完成后，native 先作为可选；稳定后默认；
- freeze/live 保留一个版本做回退；
- 删除/停用 WebView shot 预热（native 不需要每屏 WebView）；
- 保留 Tauri 主窗口、设置、剪贴板、另存对话框、托盘。

---

## 8. 性能目标与风险

| 指标 | 目标 |
| --- | --- |
| 热键 → active 可见 | ≤ 200ms（4K ≤ 300ms） |
| 热键 → 所有屏可见 | ≤ 400ms |
| 拖选/画笔 | 60fps |
| 选区/标注偏移 | 0px（物理像素 1:1） |
| 复制 4K | ≤ 150ms |
| 另存 4K | ≤ 800ms |
| 内存 | 3×4K 峰值 ≤ 200MB |

风险与对策：

| 风险 | 对策 |
| --- | --- |
| 原生文字 IME 复杂 | 用 EDIT/RichEdit，不自实现 IME |
| GDI 画质/闪烁 | 双缓冲 DIB；必要时 Direct2D |
| 多屏 DPI | 只用 Win32 rcMonitor + per-monitor v2；测试矩阵 |
| 两套路径维护 | native 稳定后删 freeze/live WebView 覆盖层；保留一个版本回退 |
| 贴图/另存行为回退 | 先复用现有命令，逐项替换 |
| 工期膨胀 | N0/N1 分批；N2/N3 按需 |

---

## 9. 验收

1. 热键 → active 可见 ≤ 200ms；无白闪/偏移。
2. 冻结图 1:1；100%/125%/150%/200% 对齐。
3. 多屏、负坐标、竖屏正确。
4. 矩形/箭头/画笔/文字/撤销可用；中文 IME 正常。
5. 复制/另存/贴图包含标注；取消/退出清理干净。
6. 连续 10 次截图不残留窗口/内存。
7. native 开关关闭可回退 freeze/live。
8. 不再出现 WebView surface/DPI 偏移。

---

## 10. 这一轮不做什么

- 不引入 Qt / ONNX / OpenCV 全家桶；只在 N3 按需加。
- 不一次做 OCR/长截图/GIF；先把冻结/选区/标注做稳。
- 不保留全屏 WebView 作为默认截图层；它只做设置/主界面。
- 不用 CSS transform 或 WebView2 surface 去补偿偏移。
- 不追求 PixPin 全部功能；先对齐快、不偏、能标注。

---

## 11. 一句话

PixPin 的快和稳来自原生窗口 + 原生场景；到点要把冻结节换成 Win32 + DIB/Direct2D，Vue 退回主界面和设置。先 N0 原生冻结/选区，再 N1 原生标注/文字；OCR、长截图、GIF 后置。
