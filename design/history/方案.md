# 版本历史与回滚 · 方案

> 目标：每一条内容（待办、计划、备忘录）都能查看到它过去的每一版，并能回到其中任意一版。
> 原则：以「实体」为版本单位，不按整个文件；全量快照 + 内容去重；恢复本身也产生一个版本。
> 前置：备忘录已落地（notes/index.json + 单篇文件 + attachments），历史从第一天就覆盖三类内容。

## 0. 一页结论

| 项 | 决定 |
| --- | --- |
| 版本单位 | 单条待办 / 单份计划 / 单篇备忘录，各自独立 |
| 存什么 | 全量快照（JSON），按内容哈希去重 |
| 何时记 | 用户可感知的变更记一条；自动保存按 5 分钟合并 |
| 存哪 | history/ 目录，每条一个追加文件 |
| 查看 | 编辑抽屉里的「历史」页 + 全局「最近变更」 |
| 恢复 | 用旧快照覆盖，恢复动作本身再记一条（可再撤回） |
| 删除 | 删除也记一条带快照的版本，支持从历史里救回来 |
| 保留 | 每条 50 版 / 90 天；全局 200MB，超了从最旧删 |

## 1. 目标与不做什么

**做**

- 任意一条内容，能看到它的版本列表：时间、改了什么、完整内容；
- 能恢复到任意一版，包括已经被删除的条目；
- 恢复后可再撤销回恢复前。

**不做**

- 多人协作的实时合并（没有多端实时场景）；
- 逐字符的富文本 diff（做块级 + 纯文本对比就够）；
- 跨设备共享历史（历史是本机的，云同步只同步最新状态）。

## 2. 记什么

| 触发点 | 原因标记 | 是否立即记 |
| --- | --- | --- |
| 新建待办 / 计划 / 备忘录 | create | 是 |
| 改标题、时间、优先级、备注 | edit | 是（5 分钟内合并） |
| 勾完成 / 取消完成 | toggle | 是 |
| 阶段完成 / 取消 | stage | 是 |
| 跳过这一次 | skip | 是 |
| 延期（拖珠子 / 推后） | snooze | 是 |
| 删除 | delete | 是（带完整快照） |
| 恢复历史 | restore | 是（记录恢复前后的 id） |
| 备忘录正文自动保存 | autosave | 5 分钟内只留最后一版 |

**为什么区分**：备忘录每 800ms 就可能存一次，全记会一天几千条。节流规则见第 4 节。

## 3. 存储模型

~~~text
<数据目录>/history/
├─ index.json                 全局轻量索引（用于「最近变更」列表）
├─ todos/<id>.jsonl           每行一个版本
├─ plans/<id>.jsonl
├─ notes/<id>.jsonl
└─ trash/<id>.jsonl           已删除实体，保留 90 天
~~~

每行结构：

~~~json
{
  "v": "9f1c2a7d",
  "at": 1793180000000,
  "reason": "edit",
  "hash": "3b7c…",
  "size": 412,
  "snapshot": { "...": "该实体的完整 JSON" }
}
~~~

- **v**：版本 id，由 at + hash 截断生成，稳定且短。
- **hash**：快照内容哈希。与上一版相同就不写（避免重复）。
- **快照是全量**：恢复时直接整条替换，不需要重放 diff，出错面最小。

**为什么不存 diff**：实体都很小（一条待办几百字节，一份计划几 KB），全量存换来的确定性远大于省下的空间。备忘录正文大一些，用配额限制（第 8 节）。

## 4. 节流与合并

- 同一实体，**5 分钟内的多次 edit 合并成一条**：只更新最后一版的 snapshot，不追加新行。
- 但以下情况强制新开一条：标题变了、时间变了、完成状态变了、删除、恢复。
- 自动保存（备忘录）10 秒内的连续保存只保留最后一条。

实现上：内存里维护 lastRecordAt / lastReason，写之前判断。

## 5. 查看

### 单条历史（编辑抽屉）

抽屉顶部加一个「历史」按钮，点开是右侧栏：

~~~text
历史 · 1.2 版本提测清单
────────────────────────
今天 10:32   改时间          查看
今天 09:15   改标题          查看
昨天 18:40   完成阶段「提测」 查看
10/28 14:02  新建            查看
────────────────────────
         [ 恢复到这个版本 ]
~~~

- 列表项显示：时间 + 一句变更摘要（由 reason 和字段差生成）。
- 点「查看」进入只读预览，顶部有黄色提示条：你正在看 10/28 14:02 的版本。
- 预览里点「恢复到这个版本」→ 二次确认 → 覆盖当前。

### 全局「最近变更」

设置或侧栏里一个入口，列出所有实体最近 50 条变更：哪条、什么时间、做了什么。用于「我记得昨天改过但忘了是哪条」。

### 变更摘要怎么来

- 待办 / 计划：字段级比较（标题、时间、优先级、阶段、完成态），生成「改时间 10/28 → 10/29」这类句子。
- 备忘录：块级比较，只说「新增 2 段」「修改第 3 段」，不逐字对比。

## 6. 恢复

**语义**：用历史快照整条覆盖当前状态。

~~~text
点「恢复」
  → 先把当前状态记一条版本（reason: before-restore）
  → 用选中快照覆盖
  → updatedAt 设为当前时间
  → 再记一条（reason: restore）
  → 界面刷新 + 云同步标脏
~~~

四个必须处理的点：

1. **恢复可撤销**：恢复前先存当前版本，用户点错了还能回去。
2. **updatedAt 用当前时间**：不然云同步会认为本地更旧，把它覆盖掉。
3. **恢复已删除的条目**：条目在 trash/ 里，恢复时从 trash 移回并重新写进 store.json；id 保持不变，避免引用断链。
4. **恢复后要推同步**：设置 dirty，让云同步线程在防抖后推一次。

## 7. 命令（Tauri）

~~~rust
history_list(kind: String, id: String) -> Vec<VersionMeta>
history_get(kind: String, id: String, v: String) -> VersionDetail
history_restore(kind: String, id: String, v: String) -> EntityEnvelope
history_recent(limit: u32) -> Vec<VersionMeta>
history_prune() -> PruneReport        // 手动清理，设置里也有按钮
~~~

- VersionMeta：{ v, at, reason, summary, size }
- VersionDetail：{ meta, snapshot }
- EntityEnvelope：{ kind, id, entity }，前端据此刷新对应列表

## 8. 清理与配额

| 规则 | 值 |
| --- | --- |
| 每条实体保留 | 最近 50 版 |
| 时间上限 | 90 天 |
| 大对象（> 256KB，主要备忘录） | 最近 20 版 + 每天 1 个基线 |
| 全局配额 | 200MB |
| 超配额 | 从最旧的开始删，跳过每天基线 |
| 删除实体的历史 | 进 trash，90 天后清 |

清理时机：应用启动后 30 秒跑一次（后台线程），以及每天一次；设置里提供「立即清理」。

## 8.5 附件与历史的关系（备忘录特有）

历史里存的是快照，快照里有 attachments 列表；但附件文件本身只有一个，按 sha256 命名。

问题：现有的附件 GC 只看**当前索引**里还被谁引用。一旦某个旧版本引用了后来被删掉的图，恢复那一版就会显示裂图。

规则：

1. GC 扫描范围从「当前索引」扩大到「当前索引 + 全部历史快照中的 attachments」；
2. 附件宽限期与历史保留期对齐（90 天），不再用 7 天；
3. 恢复旧版本时，若附件缺失，显示占位块并提示「这张图已被清理」，不阻塞正文。

## 10. 里程碑

| 阶段 | 交付 | 验收 |

| M1（2.5d） | 记录 + 存储 + 去重 + 清理（待办 / 计划 / 备忘录三类都接） | 改 10 次能看到 10 条，重复内容不重复记 |

## 11. 风险

| 风险 | 对策 |
| --- | --- |
| 自动保存灌爆历史 | 5 分钟合并 + 10 秒去抖 |
| 备忘录快照太大 | 256KB 以上降级为 20 版 + 每日基线 |
| 恢复把同步搞乱 | 恢复后 updatedAt = now，并立即标脏 |
| 历史本身被写坏 | JSONL 追加写，单行损坏只丢一条；读取时跳过坏行 |
| 恢复旧版时图片已被 GC | GC 扫描历史引用 + 宽限期对齐 90 天；缺失时占位提示 |
| 磁盘占用 | 全局 200MB 上限 + 启动清理 |

- [ ] 删除一条，30 天后历史仍在 trash，能救回
- [ ] 备忘录连续自动保存 20 次，历史里不超过 3 条
